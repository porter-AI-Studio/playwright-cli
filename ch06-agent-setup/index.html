第 6 章 · Part 2：安裝與環境設定

在 Claude Code / Codex 裡啟用 skill 並驗證

安裝指令兩家共用，差別在各自的 skill 探索與終端權限。

安裝指令：兩家一模一樣

Claude Code 和 Codex 用的是同一組指令，沒有 --claude 或 --codex 這種廠商專屬旗標：

playwright-cli install --skills
playwright-cli --help

install --skills 只是把 local skill 檔寫進 workspace；每個 host agent 自己決定何時、如何把 local skill 讀進 context。 現行版本的 playwright-cli --help 會印出已安裝的 skill 路徑，這是找 skill 最權威的方式——別自己猜路徑或手動搬檔。

一次跑得完的驗證清單

把驗證拆成一連串窄關卡，壞了才知道壞在哪一段：

  1. 確認 Node 20 以上。
  2. 裝好 @playwright/cli，playwright-cli --help 能跑。
  3. 跑 playwright-cli install --skills，從 help 輸出確認 skill 路徑出現。
  4. 手動開一次 demo，允許首次瀏覽器下載。
  5. 確認終端印出 page URL、title 和一條 snapshot 路徑。
  6. 叫 Claude Code / Codex 用 playwright-cli 做一個有界限的動作。
  7. 確認它讀了一份新的 snapshot、產出了要求的檔案。
  8. 平行使用前，給每個 agent 一個命名 session。

手動 smoke test

playwright-cli open https://demo.playwright.dev/todomvc/ --headed
playwright-cli type "Buy groceries"
playwright-cli press Enter
playwright-cli snapshot
playwright-cli check e21
playwright-cli screenshot --filename=todo-complete.png

--headed 讓瀏覽器可見，方便學習觀察；無人值守的 agent 流程省略它、用預設 headless。 每個動作後，輸出會再反映一次當前頁面。e21 是範例輸出，不是固定選擇器——讀你自己那次 snapshot 印出的 ref。

叫 agent 做一個有界限的動作

Claude Code 和 Codex 用同一句 prompt，第一次驗證時明確點名 playwright-cli：

用已安裝的 Playwright CLI skill 和 playwright-cli 檢視
https://demo.playwright.dev/todomvc/。確認頁面標題、新增一筆
待辦、讀一份新的 snapshot、存一張截圖。不要用 npx playwright test。
💡
看行為，不看它有沒有念出 skill 名字

一次成功的 smoke test 應該同時滿足：agent 用 playwright-cli（不是 npx playwright test）驅動瀏覽器、選 ref 前先讀當前 snapshot、把 ref 當短命的、寫出截圖並回報實際路徑、守在 prompt 給的目標與資料邊界內。agent 說「我載入了 Playwright skill」但沒有實際輸出，不算數。

skills-less fallback

如果 agent 沒有浮出 skill，用官方認可的無 skill 模式：叫它跑 playwright-cli --help 再用這個 CLI。 這能證明卡點是「skill 探索」還是「指令執行」。別自己塞發明的語法給 agent。

# Claude Code 綁定一個命名 browser session
PLAYWRIGHT_CLI_SESSION=todo-app claude .

這個環境變數只是選定 browser session，不會安裝 skill。驗證時用命名 session 很有用——它擋掉另一個 agent 用預設 session 把頁面換掉、害你的 snapshot/ref 迴圈錯亂。

環境限制不是命令名稱錯

  • Linux 容器可能缺 OS 函式庫 → install-browser --with-deps。
  • 企業機器可能擋瀏覽器下載 → 檢查 proxy、TLS 檢查、對外連線。
  • 遠端 shell 沒有顯示器 → 別用 --headed，用預設 headless。
  • playwright-cli: command not found → 重跑全域安裝、看 npm 全域 bin 位置、開一個新 shell。
  • 手動指令能跑但 agent 不行 → 比對 agent 拿到的 shell 環境、終端核准設定、PATH、skill 讀取權限。
