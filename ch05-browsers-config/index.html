第 5 章 · Part 2：安裝與環境設定

瀏覽器安裝、設定檔與環境變數

首次 open 會自動抓瀏覽器；其餘行為靠設定檔與環境變數調。

瀏覽器：多數情況不用手動裝

第一次跑 playwright-cli open 時會自動下載預設瀏覽器。要顯式安裝（準備機器映像、單獨診斷下載、或選非預設引擎）時：

playwright-cli install-browser              # 裝預設 Chromium
playwright-cli install-browser firefox      # 指定 Firefox
playwright-cli install-browser --with-deps  # 連系統相依一起裝（主要用在 Linux）

這個指令還支援 --dry-run（先看它打算做什麼）、--list（看有哪些可裝的瀏覽器）、--force、--only-shell、--no-shell。

⚠️
兩組 install 指令別混用

agent CLI 用 playwright-cli install-browser；Playwright Test / library 用 npx playwright install。兩者都會裝 Playwright 管理的瀏覽器，但屬於不同的可執行檔，語法不能互換。

要用系統已裝的 Chrome / Edge channel（省一份 Chromium 下載）：

playwright-cli open https://example.com --browser=chrome
playwright-cli open https://example.com --browser=msedge

設定檔：.playwright/cli.config.json

Playwright CLI 預設會讀專案裡的 .playwright/cli.config.json，你也可以用 --config 指定路徑：

playwright-cli --config path/to/config.json open example.com

一份實用的最小設定長這樣（大括號在頁面上會正常顯示）：

{
  "browser": {
    "browserName": "chromium",
    "launchOptions": { "headless": true },
    "userDataDir": ".playwright/profile"
  },
  "network": {
    "allowedOrigins": ["https://your-app.com"],
    "blockedOrigins": []
  },
  "timeouts": { "action": 5000, "navigation": 30000 },
  "outputDir": "./.playwright-cli"
}

schema 裡比較常用的欄位：

欄位作用
browser.browserNamechromium / firefox / webkit
browser.isolatedprofile 只留在記憶體、不落地
browser.userDataDirpersistent profile 目錄（不設會用臨時目錄）
browser.launchOptions傳給 Playwright 的啟動選項，如 channel、headless、executablePath
browser.contextOptionscontext 選項，如 viewport
browser.cdpEndpoint / remoteEndpoint連既有瀏覽器 / 既有 Playwright server（見 第 13 章）
outputDirsnapshot / 截圖 / trace 的輸出目錄，預設 .playwright-cli/
console.levelerror / warning / info / debug
network.allowedOrigins / blockedOrigins限制瀏覽器可請求的來源
testIdAttributetest id 屬性名，預設 data-testid
timeouts.action / navigation動作 / 導航逾時（毫秒）
codegen動作旁要不要附等效程式碼；none / typescript（預設）/ python / java / csharp
💡
省 token 是內建行為，不是切一個全域開關

實測（0.1.19 版）：open / click 這類動作結束後自動附的 snapshot，本來就只回傳檔案路徑（存進 outputDir，預設 .playwright-cli/），不會把整份 YAML 印進終端。真正會佔 context 的是你自己主動呼叫的 snapshot / eval / request 這類指令——不加 --filename 就整包印到 stdout；加了就跟自動 snapshot 一樣只回路徑。這正是 Playwright CLI 省 token 的來源（見 第 2 章）。

環境變數：前綴是 PLAYWRIGHT_MCP_

大部分設定都能用環境變數覆蓋，前綴沿用 MCP 時代的 PLAYWRIGHT_MCP_（不是 PLAYWRIGHT_CLI_）。常用的幾個：

變數作用
PLAYWRIGHT_MCP_HEADLESS是否 headless（預設 headless）
PLAYWRIGHT_MCP_BROWSERchrome / firefox / webkit / msedge
PLAYWRIGHT_MCP_DEVICE模擬裝置，如 "iPhone 15"
PLAYWRIGHT_MCP_VIEWPORT_SIZE如 "1280x720"
PLAYWRIGHT_MCP_OUTPUT_DIR輸出目錄
PLAYWRIGHT_MCP_USER_DATA_DIRprofile 目錄
PLAYWRIGHT_MCP_ISOLATEDprofile 只留記憶體
PLAYWRIGHT_MCP_TIMEOUT_ACTION / _NAVIGATION逾時（毫秒）
PLAYWRIGHT_MCP_ALLOWED_ORIGINS / _BLOCKED_ORIGINS分號分隔的來源清單
PLAYWRIGHT_MCP_PROXY_SERVER / _PROXY_BYPASSproxy 設定
PLAYWRIGHT_MCP_SECRETS_FILEdotenv 格式的機密檔
PLAYWRIGHT_MCP_STORAGE_STATEisolated session 的 storage state 檔
PLAYWRIGHT_MCP_CAPS額外能力，如 vision,pdf
PLAYWRIGHT_CLI_SESSION唯一用 PLAYWRIGHT_CLI_ 前綴的：綁定 agent process 的 session 名（見 第 10 章）
⚠️
allowedOrigins / blockedOrigins 不是安全邊界

官方明講：它們不作為安全邊界、也不影響 redirect。blocklist 先於 allowlist 評估。要真正隔離網路，用 OS / 容器層的手段。

常見踩雷

  • 改了 config 但檔案不在預設的 .playwright/cli.config.json，又沒帶 --config → 設定沒生效。
  • 把環境變數前綴打成 PLAYWRIGHT_CLI_*（除了 PLAYWRIGHT_CLI_SESSION）→ 不會報錯，只是沒作用。
  • 在無顯示的遠端 shell / 容器裡把 headless 關掉 → 啟動失敗。headless 是預設，通常別動。
