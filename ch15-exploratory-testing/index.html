第 15 章 · Part 5：AI Agent 實戰工作流

用 Claude Code + Playwright CLI 做探索性測試

AI 負責操作與記錄，人負責挑旅程與判讀結果。

兩種測試回答不同的問題

自動化測試回答的是「我們預期的行為還在嗎」；探索性測試回答的是「有沒有我們沒想到的問題」。 後者以前很難跟自動化兼顧，因為探索需要人一邊操作、一邊觀察、一邊設計下一步。Claude Code + Playwright CLI 把「操作與記錄」的成本壓到很低， 讓你把力氣放回真正需要人的地方：設計 charter、判讀結果。

tour testing：用 charter 給探索一個方向

James Whittaker 的 tour testing：把待測系統想成一座城市，每個 tour 就是一個 charter，定義這趟探索的主題與策略。常用的幾個：

Tour做什麼
Landmark挑出系統的重要功能當地標，規劃一條路線依序造訪，確認每個轉換順暢
Saboteur故意做開發者不希望你做的事：空白輸入、超長字串、貼表情符號、快速連按、中途重整
Obsessive-Compulsive同一個動作重複很多次，或做完立刻復原再做，看狀態還正不正確

流程：Claude 產生場景，人 review

charter 只給方向，具體操作交給 Claude 展開、人再挑：

請先用 playwright-cli 開啟 https://demo.playwright.dev/todomvc 了解功能。
我要用 tour testing 做探索性測試，charter 選定：
Landmark、Saboteur、Obsessive-Compulsive。

請為每個 charter 產生 3 個具體場景，每個包含：
操作步驟概要、想觀察的重點、預估時間。
先不要執行，列出來讓我 review 挑選與修改。

Claude 回一份場景清單後，換人上場：刪掉重複或價值低的、補上你在意但它沒想到的風險、確認每個場景在預估時間內做得完。 這一步花五分鐘，卻決定整個 session 的品質——charter 和場景的取捨是人的判斷。

走法一：讓 Claude 直接開瀏覽器探索

用 playwright-cli 開啟 https://demo.playwright.dev/todomvc，
執行剛剛 review 過的 Saboteur 場景 1 和 2。

規則：
1. 每做一個動作，先說明你的假設，再操作，再記錄實際結果
2. 發現可疑行為時，嘗試縮小重現步驟
3. 全部做完後，把過程整理成 session-notes.md

Claude 靠每步的 snapshot「看」畫面，會回報「輸入純空白字串後按 Enter 沒有新增項目，符合預期」這類觀察。 你隨時可以插話改方向——「剛剛那個編輯後按 Escape 的行為，再多試幾種情況」——這正是探索性測試的精神：下一步由上一步的發現決定。

走法二：把場景寫成 Playwright 測試檔再執行

把剛剛 review 過的 Obsessive-Compulsive 三個場景，
寫成 Playwright 測試檔 tests/explore-oc.spec.ts：

1. 每個場景寫成獨立的 test，標題用中文描述假設
2. 對「不確定什麼才是正確行為」的地方，不要用 expect 斷言，
   改用 test.info().annotations 記錄實際觀察
3. 寫完後執行 npx playwright test --trace on，再產出 findings.md
💡
不確定「正確答案」時，用 annotation 記錄而非硬寫斷言

探索性測試很多時候你還不知道正確行為是什麼。先用 annotation 把觀察記下來，等人工判讀 findings.md、確認哪些行為是對的之後，再把它們升級成正式的 regression 測試。

混搭策略

實務上常這樣：先用走法一跑 Landmark 摸清地形，過程中發現可疑區域，再請 Claude 把該區域寫成走法二的腳本， 用 Obsessive-Compulsive 的方式重複轟炸。走法一負責「找到值得深挖的地方」，走法二負責「挖深並留下證據」。

報告與分工

請把這次探索整理成 exploratory-report.md：
- Charter 與執行的測試場景
- 測試環境（URL、瀏覽器、日期）
- 涵蓋範圍：探索了什麼、刻意沒探索什麼
- 問題清單：每個附重現步驟、實際結果、預期結果、嚴重度（由我人工判定，先留空）
- 觀察與疑問：不確定是否為問題的行為
- 建議的後續 charter
⚠️
嚴重度留給人判定

AI 可以觀察和記錄，但「這個行為對使用者是不是問題」「要不要開 bug ticket」的判斷，留在人手上。session 建議限時 60–120 分鐘，用 AI 輔助後通常 30 分鐘內能跑完一個 charter 底下挑出的場景。
