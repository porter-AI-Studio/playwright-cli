第 13 章 · Part 4：進階能力

attach 既有瀏覽器：CDP、extension 與視覺儀表板

讓使用者先登入、過 2FA，agent 再接手後續操作。

為什麼要 attach

概念類似 Computer Use / browser-use：使用者在自己的瀏覽器手動登入、過驗證碼，agent 再附加上去做後續操作。 好處是完全不用把密碼交給程式、不用處理 2FA、session 狀態跟平常使用一模一樣，反自動化偵測也比較不容易觸發。

三種 attach

playwright-cli attach --cdp=chrome     # 依 channel 連本機 Chrome/Edge
playwright-cli attach --cdp=<url>      # 連一個 CDP endpoint
playwright-cli attach --extension=chrome  # 經「Playwright Extension」擴充連（Edge/Chrome）
playwright-cli detach                  # 卸離，但外部瀏覽器繼續開著

--extension 需要先在瀏覽器裝官方的「Playwright Extension」（Chrome 線上應用程式商店，ID mmlmfjhmonkocbjadbfplnigmagldckm）。設定檔對應欄位是browser.cdpEndpoint / cdpHeaders / cdpTimeout。

手動起一個可除錯的 Chrome

# 開一個帶除錯埠、用獨立 profile 的 Chrome，之後在這個視窗手動登入
google-chrome \
  --remote-debugging-port=9222 \
  --user-data-dir=/tmp/chrome-agent-profile

# 另一個終端
playwright-cli attach --cdp=http://localhost:9222
⚠️
attach 之後別 close 掉使用者的瀏覽器

要結束時用 detach，它只卸離連線、不關視窗。close 會把使用者的分頁一起關掉。

🔒
--remote-debugging-port 不要暴露到公網

它預設綁 localhost；任何能連上這個埠的人都能完全控制那個瀏覽器。遠端場景（例如 WSL 連 Windows 上的 Chrome）用 SSH port-forward，不要直接對外開。

show：視覺儀表板

playwright-cli show
playwright-cli show --annotate   # 給 UI review / 設計回饋用

儀表板有兩個視圖：

  • Session grid——所有活躍 session，每個有 live 畫面預覽、session 名、當前 URL、頁面標題。也能從這裡關掉 session 或清掉閒置 session 的資料。
  • Session detail——選定 session 的即時畫面，有分頁列、導航控制（上一頁 / 下一頁 / 重載 / 網址列）和完整遠端控制：點進 viewport 就接管滑鼠鍵盤，按 Esc 釋放。

最實用的場景是：agent 在背景跑瀏覽器自動化，你開著 show 在旁邊看進度，需要時直接介入幫它一把。

常見踩雷

  • WSL（NAT 模式）連不到 Windows 上的 Chrome 除錯埠 → 需要 port-forward 或改用 Windows 端執行；這類網路隔離問題跟工具本身無關。
  • attach --extension 沒裝 Playwright Extension → 連不上。
  • attach 後忘了 detach，直接關終端 → 連線可能殘留，用 list / kill-all 清。
