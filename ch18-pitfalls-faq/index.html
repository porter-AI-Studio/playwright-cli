第 18 章 · Part 5：AI Agent 實戰工作流

踩雷、疑難排解與 FAQ

把失敗切成「可執行檔 / skill 探索 / 瀏覽器啟動 / agent 權限」四道關卡分開查。

最常見的裝錯與用錯

  • 裝錯套件。@playwright/test 是測試 runner；@playwright/cli 才是本書的 agent 可執行檔。別看到「CLI」就自己推。
  • 拿 npx playwright test 當瀏覽器 quickstart。那個指令要 spec 檔和設定；agent quickstart 是 playwright-cli open <url>。
  • 找 --codex / --claude 安裝旗標。不存在。就是 playwright-cli install --skills，之後各 host 自己做 skill 探索。
  • 以為裝 skill 就等於有瀏覽器權限。skill 只教指令；host agent 仍需權限執行 binary、存取目標網站、開瀏覽器、寫檔。
  • 以為 npm install -g 就裝好瀏覽器。瀏覽器是首次 open 才下載。
  • 照抄指南裡的 element ref。ref 屬於當下那份 snapshot，讀你自己的輸出。
  • 在無顯示環境用 --headed。headless 是預設，遠端 shell / 容器就用預設。
  • 每個 task 都用 persistent profile。會把上次的登入 / 狀態帶進來。預設用記憶體 profile，需要才 opt-in。
  • 多個 agent 共用預設 session。會互相導航、互相改頁面。平行前先各給命名 session 或 PLAYWRIGHT_CLI_SESSION。

FAQ

playwright-cli 跟 npx playwright test 一樣嗎？

不一樣。前者是給 coding agent 的瀏覽器自動化介面；後者是 Playwright Test runner。runner 可以用 --debug=cli 暫停測試、讓 agent CLI attach 上去，但兩者是不同的命令面。

要另外裝瀏覽器嗎？

第一次跑通常不用，open 會自動下載。要單獨預裝或診斷時用 install-browser。

預設瀏覽器是哪個？

install-browser 裝的是預設 Chromium；open --browser=chrome 走的是系統 Chrome channel。需要指定引擎時用 --browser=firefox / webkit / msedge。

Codex 和 Claude Code 要用不同的 Playwright skill 指令嗎？

不用。在目標環境跑一次 playwright-cli install --skills，之後各 host 套用自己的 local skill 探索與終端政策。

一定要裝 skill 嗎？

不用。官方有 skills-less 模式：agent 自己讀 playwright-cli --help。裝 skill 是提供結構化指引、減少指令探索成本，不會改動應用或取代可執行檔。

snapshot 和截圖存在哪？

自動輸出會在每個指令的回傳裡報路徑，範例目錄是 .playwright-cli/。當檔案是交付物時，用指令支援的 --filename 明確命名。永遠讀你安裝版本印出的路徑，別假設檔名格式。

預設 session 會一直保持登入嗎？

不會。預設記憶體 profile 在瀏覽器開著時保留 cookie 與 storage，關掉就沒了。要長期保留用 persistent profile 或 state-save / state-load，並且當機密管理。
