第 3 章 · Part 1：認識 Playwright CLI

釐清「Playwright CLI」的兩種意思

舊教學說的「Playwright CLI」和本書說的，往往不是同一個東西。

在網路上搜尋「Playwright CLI」，會同時查到兩種完全不同的東西——用錯一邊查文件，會覺得指令對不起來、範例跑不動。這一章先把兩者分乾淨，後面各章才不會混著講。

舊的：npx playwright（測試框架內建）

只要裝過 @playwright/test，專案裡就自帶一個 playwright 可執行檔，透過 npx playwright <子指令> 呼叫。它是測試框架的配套工具，設計給「人」在終端機操作，而不是給 AI agent 讀取用的：

舊語意：@playwright/test 的子指令
# @playwright/test 內建的子指令（安裝測試框架就有）
npx playwright test              # 執行測試檔
npx playwright codegen           # 錄製操作、產生程式碼
npx playwright show-report       # 開啟 HTML 測試報告
npx playwright install           # 安裝瀏覽器二進位檔

這些指令行之有年，網路上大部分「Playwright CLI 教學」文章講的其實是這一套——錄製測試、跑測試、看報告。它們不是本書的主題。

新的：@playwright/cli（agent 專用工具）

2026 年初，微軟另外發布了一個獨立的 npm 套件 @playwright/cli，安裝後提供一個全新的可執行檔 playwright-cli。它跟 @playwright/test 沒有相依關係，是專門設計給 Claude Code、GitHub Copilot 這類「有 shell 可以跑指令」的 coding agent 使用的瀏覽器操作工具——也就是上一章比較的那個 CLI：

新語意：@playwright/cli 的指令
# @playwright/cli（套件名），指令叫 playwright-cli，2026 年初推出
npm install -g @playwright/cli@latest
playwright-cli open https://example.com --headed
playwright-cli snapshot
playwright-cli click e21
playwright-cli screenshot

這才是本書從第 4 章開始要深入的主角：snapshot / ref / session 管理 / 視覺化 dashboard / skills 安裝，都是這一套獨有的能力，舊的 npx playwright 完全沒有對應指令。

怎麼一眼分辨

舊：npx playwright新：@playwright/cli
套件@playwright/test（測試框架自帶）@playwright/cli（獨立套件）
呼叫方式npx playwright <子指令>playwright-cli <指令>（全域安裝後）
設計對象人，在終端機手動操作AI coding agent，透過 shell 呼叫
核心指令test、codegen、show-report、installopen、snapshot、click、screenshot…（50+ 個）
推出時間隨 Playwright 框架初版就有，行之有年2026 年初，晚於 Playwright MCP
互動模型一次性命令，執行完就結束daemon 常駐、session 可命名、狀態延續
⚠️
照抄舊教學最常踩的雷

把 npx playwright snapshot 或 npx playwright click e21 貼進終端機——這兩個指令屬於新版 playwright-cli，不是 npx playwright 認得的子指令，會直接報錯找不到指令。反過來，想錄製測試、跑測試檔，找的也不是 playwright-cli，而是 npx playwright codegen / npx playwright test。兩套命令面完全獨立，不能混用。

本書之後提到「Playwright CLI」，一律指 @playwright/cli / playwright-cli 這一套 agent 專用工具。下一章開始實際安裝它。
