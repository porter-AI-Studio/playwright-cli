第 10 章 · Part 3：核心操作模型

命名 session、persistent profile 與 storage state

多個 agent 共用一台機器時，session 隔離是必修課。

預設 profile：留在記憶體

預設情況下，瀏覽器 profile 只在記憶體裡。cookie 和 storage 在同一個 session 的多次指令之間保留， 但瀏覽器一關就沒了。這也是為什麼六條分開的 shell 指令能操作同一個 TodoMVC 頁面，而不是各自開六個瀏覽器。

playwright-cli open https://your-app.com
playwright-cli fill e3 "hello"     # 同一 session，狀態延續
playwright-cli close               # 關掉，記憶體 profile 消失

命名 session：平行且互不干擾

用 -s= 給 session 命名，就能同時跑多個獨立瀏覽器——不同角色、不同 context 各一個：

playwright-cli open https://your-app.com                 # 預設 session
playwright-cli -s=admin open https://your-app.com/admin  # 另一個 session
playwright-cli -s=example open https://example.com --persistent

playwright-cli list        # 列出所有 session
playwright-cli close-all   # 關掉全部
playwright-cli kill-all    # 強制殺掉全部瀏覽器進程
playwright-cli -s=admin delete-data   # 刪掉某個 session 的使用者資料

綁定 agent process：PLAYWRIGHT_CLI_SESSION

讓某個 agent process 啟動的所有 playwright-cli 指令都用同一個 session：

PLAYWRIGHT_CLI_SESSION=todo-app claude .

這是 playwright-cli 少數用 PLAYWRIGHT_CLI_ 前綴的變數（其餘設定用 PLAYWRIGHT_MCP_，見 第 5 章）。 也可以不設環境變數，直接叫 agent「每個指令前面加 -s=todo-app」。

⚠️
多個 agent 共用預設 session 會互相踩

兩個 agent 都用預設 session 時，其中一個導航或改動頁面，另一個的 snapshot / ref 迴圈就錯亂了。平行作業前，一定先給每個 agent 一個命名 session 或 PLAYWRIGHT_CLI_SESSION。

storage state：跳過登入流程

登入一次，把狀態存起來，之後直接載入、略過登入：

# 登入完成後存檔
playwright-cli state-save logged-in.json

# 之後的 run 直接載入
playwright-cli state-load logged-in.json

需要更細顆粒時，用 cookie / localStorage / sessionStorage 的個別指令：

playwright-cli cookie-list --domain your-app.com
playwright-cli cookie-set session_id abc123
playwright-cli localstorage-set feature_flag on
playwright-cli sessionstorage-clear
🔒
storage state 檔含 cookie 與 token

logged-in.json 之類的檔案等同一組有效憑證，當機密處理：別進版控、別在共用目錄留著。要餵機密給流程，用 PLAYWRIGHT_MCP_SECRETS_FILE 指向 dotenv 格式的檔。

persistent profile 的汙染風險

--persistent 或 --profile=<path> 會把 profile 落地，跨瀏覽器重啟保留——方便，但也把上一次 run 的登入、快取、彈窗狀態帶到下一次。 預設先用記憶體 profile；只有在「狀態存活是刻意需求」時才 opt-in persistent。
