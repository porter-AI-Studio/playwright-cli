第 4 章 · Part 2：安裝與環境設定

安裝：CLI 本體與 skills 兩層模型

一層是可執行檔，一層是給 agent 讀的說明書——兩者要分開安裝、分開驗證。

兩層是哪兩層

安裝 Playwright CLI 時，你其實在裝兩個獨立的東西：

層是什麼怎麼裝
可執行檔@playwright/cli 套件，提供 playwright-cli 這個指令npm install -g @playwright/cli@latest
skill 檔一組 Markdown 說明 + 參考指南，教 agent 有哪些指令、怎麼讀 snapshot、怎麼用 ref 操作playwright-cli install --skills

這兩層的失敗要分開查：playwright-cli --help 跑不動是可執行檔的問題；help 正常但 agent 不照工作流走，是skill 探索或 agent 權限的問題。把它們混在一起查，會浪費很多時間。

第一步：裝可執行檔

需要 Node.js 18 以上（部分官方文件寫 20+，若要跑測試生成相關功能建議直接上 20）。

# 確認 Node
node --version
npm --version

# 全域安裝
npm install -g @playwright/cli@latest

# 驗證
playwright-cli --help

--help 能正常印出指令清單，代表三件事成立：npm 解析到套件、可執行檔連進了 PATH、Node 起得動它。 現行版本的 --help 還會印出已安裝的 skill 路徑，讓 agent 不用你告訴它也能找到 skill——所以下一步裝完 skill 後，回頭看這個路徑有沒有出現。

第二步：裝 skill

在你要用的專案目錄裡執行：

cd your-project-folder
playwright-cli install --skills

這會把 SKILL.md 和一批參考指南（測試執行與除錯、request mocking、session 管理、storage state、測試生成、tracing、影片錄製、檢視元素屬性等）寫進你的 workspace。 Claude Code、GitHub Copilot、Codex 這類支援 local skill 的 agent 會自己讀它——這就是它們在不需要 MCP tool schema 的情況下學會 CLI 能力的方式。

⚠️
複製貼上會把 --skills 的兩個 hyphen 併成一個

從網頁或 PDF 複製 install --skills 時，-- 常被轉成單一長破折號，執行時報 too many arguments, expected zero and received one。手動把它改回兩個半形 hyphen 即可。

沒有全域安裝權限時

如果環境擋全域安裝，用官方認可的 npx 路徑做探索：

# 檢查有沒有本地版
npx --no-install playwright --version

# 有本地版時，所有指令改用 npx playwright cli
npx playwright cli --help
🚫
不要用 sudo npm install -g 當萬用解

它會留下 root 擁有的 npm cache 與檔案、擴大信任邊界。改用可寫的 npm prefix、受管的工具映像，或上面的 npx 路徑。

別跟 @playwright/test 搞混

這是最常見的裝錯：

# 這是「測試 runner」，不是本書講的 agent CLI
npm install -D @playwright/test
npx playwright test

@playwright/test 是拿 spec 檔跑測試套件的 runner（支援 projects、fixtures、retries、reporters）；@playwright/cli 是跨多次終端呼叫、操控一個活著的瀏覽器。一個專案可以同時裝這兩個，但裝了 test 套件不會讓 agent 得到playwright-cli 的工作流。新舊「Playwright CLI」的完整釐清見 第 3 章。

ℹ️
版本釘選

團隊要可重現的話，把 @latest 換成核可過的版本號。@playwright/cli 仍在 0.1.x 快速演進，sessions、dashboard、attach、測試生成這些能力是不同版本陸續加的——用舊版前先看它自己的 --help。
