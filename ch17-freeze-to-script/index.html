第 17 章 · Part 5：AI Agent 實戰工作流

把探索流程固化成腳本，省下 AI token

AI 的角色從「每次執行者」變成「一次性作者」。

核心思維：AI 當一次性編譯器

探索一個陌生流程時，讓 agent 用互動方式（snapshot → ref → 操作，或搭配 MCP）把路線試出來；一旦流程確定，就請它把流程寫成一支 Playwright 腳本，之後每次執行都跑這支腳本，不再啟動 AI。 寫好的程式本身就是資產：跑一百次的成本和跑一次一樣，只有當流程真的改變時才需要 AI 再出手修改。

例：每日首頁健康檢查

探索確認流程是「截圖 → 檢查關鍵元素 → 輸出報告」後，請 agent 產出這樣一支腳本：

// daily-check.mjs
import { chromium } from 'playwright';
import fs from 'node:fs/promises';

const browser = await chromium.launch({ channel: 'chrome' });
const page = await browser.newPage();

const start = Date.now();
await page.goto('https://example.com', { waitUntil: 'networkidle' });
const loadTime = Date.now() - start;

const articleCount = await page.locator('article').count();
const hasHeader = await page.locator('header').isVisible();

const today = new Date().toISOString().slice(0, 10);
await page.screenshot({ path: 'reports/' + today + '.png', fullPage: true });
await fs.writeFile(
  'reports/' + today + '.json',
  JSON.stringify({ today, loadTime, articleCount, hasHeader }, null, 2)
);

await browser.close();

之後只要排 cron 或 GitHub Actions 每天跑 node daily-check.mjs，完全不需要再啟動 AI。同樣的模式也能用來做：

  • 批次幫所有文章頁產生社群分享截圖。
  • 監控特定頁面改版（存 baseline 截圖，用 pixelmatch 做 diff）。
  • 定期抓後台數據寫進 CSV。
  • 每週產出站內連結健康檢查報告。

把頁面壓小再餵 AI

需要 AI「讀內容」而不是「看畫面」時，先寫一支小腳本把頁面轉成精簡格式再交給它：用 Playwright 抓 HTML， 搭配 @mozilla/readability 抽正文、turndown 轉 Markdown，十幾行就能把輸出壓到原始 HTML 的 5–10%， 廣告和側欄也一起濾掉。做研究、整理資料、摘要文章時，token 消耗直接砍數倍。

用 generate-locator 讓腳本更耐改

探索時你手上是 e12 這種短命 ref，寫進腳本前先 playwright-cli generate-locator e12 轉成getByRole(...) 之類的穩定 locator（見 第 9 章），腳本才不會因為一次 re-render 就壞。

探索發現轉 regression

這也是探索性測試接上自動化的地方：在探索 session 裡確認的問題，修好之後請 agent 把重現步驟轉成 Playwright spec，進 CI 防止回歸。 探索負責發現，自動化負責守住。

⚠️
不要太早固化還在變的流程

固化的前提是「流程已經穩定」。流程還在調整時就寫死腳本，只會換來一堆需要一直改的死程式碼。另外，AI 產的腳本常缺錯誤處理與逾時，接手時要補上。
