前言

前言

當 AI agent 需要看見並操作瀏覽器，怎麼做才不會把 context window 燒光——這本書從頭到尾在回答這件事。

這本書要解決什麼問題

Playwright CLI（npm 套件 @playwright/cli）是 Microsoft 在 2026 年初推出、專為 coding agent 設計的命令列瀏覽器自動化工具。它跟 Playwright MCP 同一個團隊、同一顆引擎，差別在於把頁面快照與截圖存到磁碟、只回傳一行檔案路徑，讓 agent 自己決定要讀什麼。官方 benchmark 顯示，同一個瀏覽器任務的 token 用量可比 Playwright MCP 少約四倍。

但目前關於它的資訊散落在官方 README、playwright.dev/agent-cli/ 文件、十幾篇第三方教學和鐵人賽實戰系列裡，而且「Playwright CLI」這個詞還同時指涉舊的 npx playwright 子指令。這本書把這些整理成一條可以循序讀完的路徑：從「它是什麼、跟 MCP 怎麼選」，到安裝、snapshot → ref 操作模型、完整指令表，再到用 Claude Code / Codex 跑探索性測試、把流程固化成省 token 的腳本。讀完，你能在自己的 agent 裡把 Playwright CLI 裝對、用對，並清楚知道什麼時候該用 CLI、什麼時候留給 MCP。

這本書適合誰

  • 在 Claude Code、Codex、Copilot、Cursor 等 coding agent 裡，想讓 AI 實際操作瀏覽器的開發者。
  • 已經在用 Playwright MCP，但被 accessibility tree 和截圖塞爆 context window，想找更省 token 方案的人。
  • 負責 E2E 或探索性測試，想用 AI 產出測試草稿、再固化成正式 Playwright 測試檔的 QA 工程師。
  • 被「Playwright CLI」一詞搞混，想弄清楚它指的是舊的 npx playwright screenshot / codegen，還是新的 @playwright/cli 套件的人。

關於書裡的範例

書中的指令與輸出以官方 README、playwright.dev/agent-cli/ 文件，以及多篇第三方教學和 iThome 鐵人賽實戰系列為基礎，快照 YAML 與 .playwright-cli/ 檔名格式盡量貼近實際輸出；114k 對 27k 的 token benchmark 是 Playwright 官方數字經第三方轉述，尚未在本機逐項複現。@playwright/cli 仍在 0.1.x 快速演進（本書對應約 v0.1.19，2026 年 9 月），指令面在小版本之間持續擴充——書中某個指令若跟你手上的版本對不上，以 playwright-cli --help 的實際輸出為準。

素材裡記到的坑也一併寫進正文，而不是只講順風路徑：新舊語意混淆放在第 3 章、skill 沒被 agent 讀到放在第 6 章、session 狀態誤解與其他常見錯誤集中在第 18 章。
