第 12 章 · Part 4：進階能力

codegen、recording、tracing 與 video

把操作變成程式碼、把執行變成可回放的證據。

新舊「錄製」的差別

舊：npx playwright codegen新：playwright-cli recording-start/stop
啟動方式另開瀏覽器 + Playwright Inspector 兩個視窗在目前的 session 裡開始 / 停止錄
輸出即時翻譯，支援 --target 多語言、-o 輸出檔停止時把動作印成 Playwright code
適合人手動錄一份草稿agent 探索完，把剛才那段固化成程式碼

兩者都屬「Playwright CLI」這個名字底下——差異的完整說明見 第 3 章。

recording：把操作錄成程式碼

playwright-cli recording-start
# ... 用 click / fill / press 走一遍流程 ...
playwright-cli recording-stop
# 停止時印出對應的 Playwright code，偏好 getByRole / getByText 這類語意化定位
⚠️
錄出來的只是「第一份草稿」

它缺斷言（expect()）、沒有 Page Object 結構、遇到動態內容容易 flaky、沒有錯誤處理。實務做法是：先錄一份打底，再由你或 agent 重構——抽可重用函式、補斷言、拆測試案例、處理等待。把它接到正式測試的流程見 第 16 章。

tracing：可逐步回放的 trace

playwright-cli tracing-start
# ... 執行流程 ...
playwright-cli tracing-stop

停止時會列出三份產出，全部存在 .playwright-cli/traces/ 下：trace-<timestamp>.trace（動作紀錄）、trace-<timestamp>.network（網路紀錄）、和 resources/（快取的頁面資源）。 直接把 .trace 檔路徑餵給 trace viewer 就能開，不用先打包成 zip：

npx playwright show-trace .playwright-cli/traces/trace-1788418742977.trace

trace 保留每一步的畫面快照、DOM 狀態和網路請求。這是探索性測試長年痛點——「剛剛那個 bug 我重現不出來了」——的解方： 把 trace 檔直接附在 bug ticket，開發者用 trace viewer 逐步回放。

video：帶章節標記的操作影片

playwright-cli video-start run.webm
playwright-cli video-chapter "登入"
# ... 操作 ...
playwright-cli video-chapter "結帳"
playwright-cli video-show-actions     # 在影片上標註每個動作
playwright-cli video-hide-actions
playwright-cli video-stop

video-start 直接帶檔名就會實際錄檔（實測：video-start demo.webm 接幾個動作、video-stop 收尾，當場產出可播放的 .webm），不需要額外在設定檔加什麼欄位。 想指定畫面尺寸就加 --size，例如 video-start demo.webm --size=800x600；不指定則自動配合錄到的內容縮放到 800×800 內。

DevTools 檢視指令

playwright-cli console error        # 只看 error 以上的 console 訊息
playwright-cli requests             # 頁面載入後的所有網路請求
playwright-cli request 3            # 第 3 個請求的細節
playwright-cli run-code --filename=snippet.ts   # 跑一段完整 Playwright 程式

常見踩雷

  • video-start 沒產檔 → 忘了呼叫 video-stop 收尾，或路徑所在目錄不存在。
  • 想用文字編輯器讀 trace → .trace / .network 是內部格式，要用 npx playwright show-trace 開。
  • 把 recording 產出直接當測試用 → 先重構（補斷言、去 flaky）。
